# ADiV Offline Upgrade — Baseline Audit

**Audited:** 2026-11-02 · **Baseline:** `main` at `3e4f41f` (clean before this work)

## Existing implementation

- Mobile app: Expo SDK 58.0.22, React Native 0.88.1, Expo Router, TypeScript, MapLibre RN 11.5.1 (MapLibre Android native 13.6.1), Convex 1.48.0.
- Android is the documented mobile target. Native folders are generated by CNG; there is no checked-in `android/` or `ios/` project. No Android device is attached to this session.
- Ride recording is in `mobile/src/app/record.tsx`; location updates are delivered by `expo-location`/`expo-task-manager`. Accepted points are currently serialized to AsyncStorage under `adiv-active-ride`.
- The recorder can start, pause, resume and discard. It has no normal end action. Restored points are always put into the “Ride finished” summary, even after an interrupted recording.
- Route planning calls the public OSRM demo over HTTP. The map style is a remote CARTO style. Neither is an offline capability.
- New GPS ride saves currently upload an encoded route polyline to Convex. This upgrade will keep future route points local and upload only ride summary fields.
- Convex is an unauthenticated single-bike backend. There is no account identity or user scope. Keep this model; do not add user IDs or user-scoped sync.
- The mobile app has no local SQLite store, package manager, offline search index or native routing module. The root Vitest suite only includes `__tests__/**`; mobile has typecheck/lint scripts but no separate test runner.

## Implementation gates

1. Preserve existing network behavior and feature set while introducing additive local storage.
2. Build the local PMTiles and Valhalla spikes against the exact locked native versions. Validate zero network requests, cold restart and route behavior on a physical Android device before exposing offline support.
3. Keep the current online OSRM/CARTO path explicitly labeled online. Missing/corrupt local data must fail visibly and safely.
4. Do not upload GPS points or route geometry for new rides. Existing Convex route values remain readable.
5. Run mobile lint/typecheck and root unit tests. Convex source changes receive local type verification; deployment is a separate release action.

## Known evidence gaps

- No physical Android validation was possible during this audit (no device listed by `adb devices`).
- No Philippine map, routing graph or search asset is checked into this repository. Asset sizes, attribution bundle, routing compatibility and real-device performance remain unmeasured.
- No iOS offline support is claimed.

## Implementation status (2026-11-02)

- GPS ride state, points, and the summary outbox now use Expo SQLite on Android. The old AsyncStorage active ride migrates to an interrupted/recovered SQLite ride. The recorder has explicit Pause, Resume, End, Save, and Discard paths; paused time is excluded from the recorded duration. Local history loads summaries first and reads full tracks only for GPX export or Share Studio.
- Convex ride creation accepts an optional stable client ride ID and deduplicates retries. New uploads contain ride metadata and totals only; local GPS points remain on-device.
- Android has a versioned folder-pack manager with file checksums, required local PMTiles/style/FTS5 assets, staging before activation, rollback by reactivating a previous installed version, explicit verification, and active-pack protection on delete. Search uses local SQLite FTS5, with coordinate and map-pin fallbacks.
- The first generated Android pack was `ph-davao` v1.0.0, built from the Geofabrik Philippines extract pinned to 2026-10-31. It covers `[125.2, 6.8, 125.75, 7.45]`, uses Shortbread 1.1 vector tiles, includes a local style, glyphs/sprites, attribution/licenses, and an FTS5 database with 15,527 named places and roads. The PMTiles archive passes `pmtiles verify`; the complete manifest contains checksums for 262 packaged files. This initial pack was approximately 11.5 MB.
- The updated Davao pack v1.0.1 is at `mobile/builds/ADiV-Davao-1.0.1`; it has 264 files and is approximately 17.7 MB. It includes the expanded POI/street search index and local text layers. It was transferred to the Xiaomi's Downloads directory; APK 1.3.4 later imported it successfully and the user confirmed map rendering and local search in Airplane mode.
- A PowerShell compatibility issue in the pinned water-source fetcher was fixed: single-value HTTP headers are normalized from arrays and JSON timestamps are normalized before comparison. The pinned water archives and Philippines PBF passed their size/hash checks.
- OSRM remains the only route provider and is labeled online. It reroutes only after three consecutive fixes more than 120 m from the route, with a 45-second cooldown. Ferry and motorcycle-access limits are disclosed.
- Physical smoke checks were completed on 2026-11-02 using a Xiaomi 23013PC75G (`mondrian`). The first preview APK exposed a backend mismatch (`fuel:getFuelInsights` was missing) and a gray recorder basemap. A dedicated empty Convex dev deployment was then created and populated with this checkout's functions, and EAS Preview was pointed to it. The rebuilt APK launches into first-time bike setup against that target. The dashboard's `fuel:getFuelInsights` query has not been exercised in this empty-bike state; ride recording and sync were not exercised.
- On 2026-11-02, importing the transferred pack from app version 1.3.2 found `FileSystemFile.copy` failing because the destination path did not exist. Version 1.3.3 added destination-parent creation and passed that copy step, but pack validation then reported `map/davao.pmtiles` missing. The recursive copier had descended into `map/` and appended the full relative path again, placing the file under `map/map/`. Version 1.3.4 now appends only each entry's basename at the current destination directory.
- APK 1.3.4 (version code 14, ARM64) was built locally in WSL, installed in place over ADB, and launched on the Xiaomi. The user confirmed the Davao v1.0.1 pack installed from Downloads and later confirmed that its map renders in Airplane mode and place search returns results. Search felt slow; the result list would not scroll; choosing a result took a long time and left stale “No mapped match” text even though the destination moved. Navigation was not started, so route guidance and automatic rerouting remain unverified. ADB `input tap` is blocked by this Xiaomi's `INJECT_EVENTS` security restriction; further UI checks need physical taps. SQLite recovery after process death, background recording, recorder start/end/save, notification actions, and sync retry behavior remain untested on the device. Offline routing is deferred; no native Valhalla bridge has passed validation.
- Follow-up changes for APK 1.3.5 bound Photon/OSRM requests, render offline results before waiting for Photon, expose the reroute threshold (3 GPS fixes over 120 m with a 45-second cooldown), and explain that rerouting remains online-only. The ended-ride view now opens an interactive full-screen route overview with endpoint recenter; the completed local ride retains its track, distance, average/max speed, and map on the Rides page. Distance suppresses accuracy-sized GPS jitter, and maximum speed rejects isolated GPS spikes. Local typecheck, lint (warnings only in existing platform stubs), and the root unit suite passed. The user confirmed both offline search queries return results, but reported slow processing and a results list that would not scroll. Physical verification of the new interactions, off-route recalculation, notification metrics, saved ride, and GPS estimates remains pending.
- APK 1.3.5 / code 15 was built in WSL locally for `arm64-v8a`; size 57,683,095 bytes, SHA-256 `752dee9356cffa49dff41456d91ad11c183a044682bec634c493720289416b13`. `aapt` confirmed package `com.damascus.adiv`, version `1.3.5`, code 15. `apksigner` verified that its certificate matches APK 1.3.4.
